# AI 協作後端程式設計評量藍圖

## 評量目的

三份考卷不是平行題庫，而是逐層驗證學生能否從「理解後端與 AI 協作基本語言」，進展到「完成可靠實作」，最後承擔「正式環境交付與事故決策」。

| 卷別 | 使用時機 | 驗證重點 | 通過後建議 |
| --- | --- | --- | --- |
| 第一份：基礎診斷 | 課前或基礎單元後 | HTTP/REST、輸入驗證、分層、安全、AI 協作閉環 | 進入 API 與資料庫實作 |
| 第二份：實作能力 | 資料庫、測試與可靠性單元後 | 交易、遷移、冪等、併發、測試、AI code review | 進入部署與正式環境整合 |
| 第三份：整合與上線決策 | 結訓或專題上線前 | 授權、安全、觀測、CI/CD、事故處理、AI 治理 | 主責或參與正式環境交付 |

每份卷為 100 分，結果除總分外，也按能力面向呈現。教師不應只看總分；任一關鍵能力低於 60%，即應安排對應實作補強。

## 問卷生命週期

系統採用以下狀態：

1. `draft`：可編輯題目、答案、配分、名單與評分規準。
2. `review`：送交課程負責人檢查效度、答案與作答體驗。
3. `published`：出現在作答清單，允許驗證身份並啟動計時。
4. `closed`：停止新作答，保留既有結果、搜尋與匯出。
5. `archived`：退出日常管理清單，仍保留版本與稽核歷程。

每次狀態變更都記錄前後狀態、時間、執行者與備註。已發布題卷若要大幅修改，產品化階段應複製為新版本，避免歷史成績對應到不同題目。
